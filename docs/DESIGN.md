# 두 사람의 작은 가게 (가제) — 게임 설계서

> 이 문서는 **설계 명세**다. 여기 적힌 수치(타이머, 확률, 한도, 엔딩일, 레이아웃 픽셀 등)는 모두 **잠정값**이고, 밸런스 시뮬레이터와 목업으로 확인한 뒤에 확정한다. 확정된 수치는 `Balance.csv`에만 둔다.
> 일정은 [PLAN.md](PLAN.md)를 따른다.
>
> 환경: Unity 6.3 LTS(**6000.3.18f1 이상**, 설치된 6000.3.25f1 사용), URP **Universal 2D** 템플릿, 화면은 전부 **uGUI + TextMeshPro**, Windows PC, 싱글·오프라인
> 역할 분담: 코드와 에디터 자동화 도구는 Claude가 GitHub 저장소로 전달한다. 에디터 작업, 아트, 개인적인 글(추억, 편지), 플레이테스트는 사용자가 맡는다.

---

## 1) 한 줄 소개

창 옆에 켜 두는 한 화면짜리 도트 가게다. 받는 사람과 나를 닮은 두 주인이 재료를 모으고, 상품을 만들고, 팔고, 강화하고, 도감을 채우며 손수레 노점을 '{가게이름}'으로 키운다. 가게가 자랄 때마다 우편함에 두 사람의 추억이 도착하고, 마지막 주문을 완성한 밤에 편지가 열린다.

- 캐릭터를 걷게 하는 조작은 없다. 모든 조작은 클릭과 메뉴로 한다.
- 하루에 몇 번 들여다보면 **보통 6~8일, 하루 1번이어도 10~12일, 어떤 경우든 14일 안에 엔딩**을 보는 것이 목표다(시뮬레이터로 확인).
- 엔딩 뒤에도 가게는 계속 열려 있다. ★5 도감, +10 강화, 숨은 업적, 비밀 편지(P.S.)를 모을 수 있다.

## 2) 테마 틀과 예시 스킨 (플레이스홀더)

### 2-1. 원칙
- **코드는 ID만 안다**(`mat_01`, `item_07`, `zone_B`, `mem_12` 등). 이름, 아이콘, 대사, 추억, 편지는 전부 데이터에 있다. 테마를 바꿀 때 코드는 한 줄도 고치지 않는다.
- 데이터의 위치는 다음과 같다.
  - `ThemeProfile` ScriptableObject 1개: 토큰 값, UI 대표색 3개, 조수 스킨
  - `Game/Assets/_Project/Data/*.csv`: 스프레드시트로 편집한다(items, recipes, upgrades, equips, helpers, achievements, memories, dialogue, orders, ui_strings, tutorial, guide_cards).
  - `Game/Assets/_Project/Content/Memories/*.txt`: 추억 본문, 편지, P.S. 사용자가 메모장으로 쓴다(UTF-8).
  - `Balance.csv`: 수치 전용. Python 시뮬레이터, 헤드리스 C# 테스트, 게임이 같은 파일을 읽는다.
- 아이콘은 **ID 파일명 규칙**(`item_07.png` 등)으로 찾는다. 그림을 바꿀 때 같은 이름으로 덮어쓰면 된다.
- **테마 검사 창**(에디터 창): 비어 있는 토큰, 빠진 아이콘, 해금 조건이 없는 추억, 아직 남은 임시 텍스트·임시 추억 N개, CSV 가져오기 오류를 빨간 줄로 보여 준다.
- **테마를 정하기 전의 개발 방식**: Claude가 쓴 **에디터 메뉴**가 사용자 PC에서 번호가 적힌 16x16 색 블록 아이콘을 만든다(Texture2D → PNG). 임시 텍스트는 CSV에 `[임시]` 표시로 넣는다. 이것만으로 처음부터 엔딩까지 끝까지 테스트할 수 있다. Claude는 PNG 같은 바이너리 파일을 커밋하지 않는다.

### 2-2. CSV 파이프라인
- 인코딩은 **UTF-8만** 쓴다. 엑셀은 반드시 'CSV UTF-8(쉼표로 분리)'로 저장하거나 Google 스프레드시트에서 CSV로 내보낸다(한국어 엑셀의 기본 CSV는 CP949라서 한글이 깨진다).
- 파서는 **RFC 4180** 따옴표 규칙을 지원한다. 문장 안의 쉼표, 따옴표, 줄바꿈이 들어가도 깨지지 않는다.
- 날짜처럼 보이는 칸(`{기념일1}`의 `03-14` 등)과 ID 칸은 **항상 문자열로 읽는다**. 엑셀이 날짜나 `1E+15`로 바꾸는 사고를 막기 위해 가이드에 '해당 열은 텍스트 서식' 규칙을 적는다.
- CSV를 저장하면 `AssetPostprocessor.OnPostprocessAllAssets`가 감지해서 **자동으로 다시 가져온다**. 수동 메뉴 `[Tools > 데이터 가져오기]`는 전체 재가져오기용으로만 남긴다.
- 가져오기 오류(열 개수 불일치, 모르는 ID, 숫자 변환 실패, 빠진 필수 칸)는 테마 검사 창에 행 번호와 함께 빨간 줄로 나온다.
- CSV 파서와 정의 레코드는 순수 C#(`Scripts/Core`)에 있다. 헤드리스 테스트와 에디터 가져오기가 같은 코드로 CSV를 읽는다. 에디터 가져오기는 여기에 아이콘 참조를 붙여 SO를 만들고, 실행 중에는 SO에서 Core 레코드를 만든다.

### 2-3. 치환 토큰 (실행 중에 치환)
| 토큰 | 용도 | 비어 있을 때 |

| `{받는사람}` | 이름·애칭. 대사, 업적, 편지에 쓰인다 | 필수 |
| `{나}` | 만든 사람. 두 번째 주인, 크레딧 | 필수 |
| `{가게이름}` | 5단계 간판, 타이틀 | 필수 |
| `{처음만난날}` → `{함께한날}` | 오늘까지 며칠인지 자동 계산 | 해당 문구를 숨긴다 |
| `{기념일1}`, `{기념일2}` (MM-DD) | 날짜 숨은 업적, 보너스 추억 | 업적을 숨긴다 |
| `{반려동물}` | 조수 1마리의 스킨과 이름 | 기본 동물 |
| `{장소1}`~`{장소4}` | 채집터 4곳의 이름 | 스킨 기본값 |
| `{좋아하는것1~3}` | 상품 이름과 설명 | 스킨 기본값 |
| `{최종상품}` | 마지막 주문 | 필수 |
| `{편지}`, `{비밀편지}` | Letter.txt, PS.txt | 필수 / P.S.는 선택 |

더 넣을 데이터도 있다.
- 두 주인 말풍선 30줄: 주인을 클릭하면 한 줄씩 나온다. 둘만 아는 농담을 넣는 자리다.
- 강화 실패 위로 문구 8줄
- **도감 설명 한 줄 × 28**(상품 20, 소품 8): 가장 값싸면서 효과가 큰 선물 채널이다.
- 둘만의 비밀 행동 1개(숨은 업적)

### 2-5. 관계 중립 구도
'두 주인' 구도는 연인, 친구, 가족 모두에 맞는다. 받는 사람 + {반려동물}, 받는 사람 + 가상 캐릭터로 바꿀 수도 있다.
받는 사람 정보는 **질문 10개**로 모은다. 답은 **6주 차까지** 받는다.
1. 좋아하는 음식
2. 좋아하는 색
3. 좋아하는 동물
4. 함께 간 곳 4곳
5. 처음 만난 날
6. 기념일
7. 부르는 애칭
8. 함께 웃었던 일
9. 고마웠던 일
10. 앞으로 함께 하고 싶은 일

### 2-6. 예시 스킨 3종 (채집터 4 → 재료 8 → 상품 4계열 × 5 → 최종 상품)
| | A. 동네 빵집 | B. 꽃집 & 정원 공방 | C. 추억 여행 기념품점 |
|---|---|---|---|
| 채집터 | 밀밭, 과수원, 닭장, 꿀벌통 | 꽃밭, 온실, 숲, 연못 | 실제로 함께 간 {장소1~4} |
| 재료(기본/희귀) | 밀/호밀, 딸기/레몬, 달걀/메추리알, 꿀/밀랍 | 데이지/장미, 허브/다육이, 나뭇가지/이끼, 연꽃/조약돌 | 조개/모래, 솔방울/단풍, 티켓/네온 조각 등 |
| 상품 계열 | 빵, 쿠키, 케이크, 음료 | 꽃다발, 화관, 향초, 테라리움 | 엽서, 스노우볼, 열쇠고리, 액자 |
| 소품 예시 | 첫 데이트 영수증, 빵 봉투 | 말린 꽃잎, 편지 리본 | 기차표, 조개껍데기 |
| 최종 상품 | 우리의 기념일 케이크 | {기념일1}의 꽃다발 | 다음 여행 티켓 |
| 어울리는 사람 | 디저트·카페를 좋아하는 사람 | 부모님, 친구 | 함께 간 장소가 뚜렷한 관계 |

- 스킨과 **스타일 기준 시트**(팔레트, 크기, 기준 그림)는 **8주 차까지** 확정한다(11절).
- 지인 플레이테스트는 개인 콘텐츠가 전혀 없는 **예시 스킨 빌드**(예: A 빵집)로 한다. 실제 콘텐츠 빌드는 선물하기 전에 사용자만 플레이한다.

## 3) 핵심 루프

### 3-1. 단계
1. **채집(클릭)**: 채집터(최대 4곳)를 클릭하거나 누르고 있으면(초당 5회) 재료를 얻는다. 크리티컬 ×5, 희귀 재료, 소품 드롭이 가끔 나온다.
2. **자동화(방치)**: 코인으로 조수를 고용한다. 조수가 초마다 채집하고, 자동 제작 슬롯과 점원이 제작과 판매를 넘겨받는다.
3. **제작**: 작업대에서 레시피를 만든다. 작업대를 클릭하면 게이지가 빨리 찬다. 완성할 때 ★1~★3이 붙고, 처음 만든 상품은 도감에 등록된다. **반짝이 가루도 제작으로 만든다**(가루의 주 공급원).
4. **판매·납품**: 상품이 진열대에 자동으로 올라가고 팔려서 코인과 하트(명성)가 된다. 주문 게시판에 납품하면 코인, 하트, 반짝이 가루, 레시피 쪽지, 소품 판정 보상을 받는다.
5. **고르기**: 남는 상품마다 셋 중 하나를 고른다.
   - 판다(코인)
   - '팔지 않음'으로 잠가 ★ 승급용으로 모은다
   - 분해한다(반짝이 가루, 보조 공급원)
6. **강화**: 코인과 반짝이 가루로 장비 6종을 강화한다(클릭량, 제작 속도, ★ 확률, 판매가 상승). 같은 상품 같은 ★ 3개로 ★ 승급을 시도한다. **실패해도 상품은 사라지지 않는다.**
7. **가게 확장**: 코인 + 하트 + 도감 수를 채우면 건축 타이머가 돈다. 건축 중에도 영업은 계속된다. 완성된 건축을 수령하면 새 채집터와 상품 계열이 열리고 우편함에 추억이 온다.
8. **기록**: 도감 계열 완성, 업적 별 마일스톤, 누적 접속일이 추억을 연다. 추억은 앨범에 붙는다.
9. **방치**: 창을 옆에 두거나 끈다. 다시 켜면 '그동안 가게에서 있었던 일' 정산 창이 뜨고, 다음 목표 바가 새 목표를 보여 준다. 그리고 1번으로 돌아간다.

### 3-2. 기둥끼리 먹여 주는 관계
| 주는 쪽 → 받는 쪽 | 연결 |
|---|---|
| 클릭·방치 → 제작 | 재료 공급. 조수 수와 창고가 병목이 된다 |
| 제작·가게 → 클릭·방치 | 코인으로 조수를 고용하고 업그레이드한다 |
| 제작·가게 → 강화 | 반짝이 가루(**제작이 주 공급원**, 주문 보상과 저★ 분해는 보조)와 코인. 제작만으로 강화에 필요한 가루가 충분히 나오는지 시뮬레이터로 확인한다 |
| 강화 → 클릭·방치 | 채집 도구 강화 1단계마다 클릭량 +30%, 조수 생산 ×1.15 |
| 강화 → 가게 | 작업대는 ★ 확률과 속도, 진열대는 판매가와 손님 유입을 올린다 |
| 수집(도감) → 메인 진행 | 도감 수가 가게 확장 조건이고, 계열을 완성하면 판매가 +10%가 붙는다 |
| 주문 게시판 → 수집·강화·엔딩 | '★3 이상 쿠키' 같은 조건, 레시피 쪽지, 소품, 단골손님 도감, 그리고 엔딩의 '마지막 주문' |
| 업적 → 전체 | 별 1개당 판매가 +0.5%(영구), 별 마일스톤마다 추억 |

## 4) 시스템 목록

복잡도는 하/중/상으로 표시한다. **필수**는 엔딩까지 가는 데 꼭 필요한 것, **권장**은 재미와 선물 완성도에 중요한 것, **선택**은 21주 차 말 기능 동결 전에 시간이 남을 때만 만드는 것이다. 일정이 밀리면 선택 → 권장 순서로 빼고, 빼기 전에 시뮬레이터로 영향을 확인한다.
- **★ 승급을 빼면** 제작은 ★1~★3만 내므로 ★4·★5가 없어진다. 이때 업적 '첫 ★4', '첫 ★5', 추억 M19('★5 10종'), 엔딩 뒤 '★5 도감' 목표를 지우거나 다른 조건으로 바꾸고, 업적 45개·추억 20개 합계와 별 마일스톤을 다시 맞춘다.

### 필수
| 시스템 | 내용 | 복잡도 |
|---|---|---|
| 코어 시뮬레이션 `Simulate(dt)` | 한 스텝의 처리 순서를 **채집 → 창고 → 제작 큐 → 진열 → 판매 → 타이머(건축·주문)**로 고정한다. UnityEngine을 전혀 참조하지 않는 순수 C#(`Scripts/Core`, asmdef의 No Engine References 켜기, C# 9 이하 문법)이다. 난수는 저장 가능한 PRNG(xorshift, `ulong` 상태)를 쓰고 그 상태를 세이브에 넣는다. Claude가 같은 `.cs` 파일을 컨테이너에서 dotnet으로 헤드리스 컴파일해 단위 테스트한다. '1초 × 3600'과 '60초 × 60'의 결과가 허용 오차 안인지 테스트한다 | 중 |
| 시간 처리 | 평소 프레임은 `Time.unscaledDeltaTime`을 누적해 1초 고정 스텝으로 `Simulate(1)`을 부른다(한 프레임에 최대 5스텝). 동시에 매 프레임 UTC 경과를 재서, 한 번에 **5초보다 큰 틈**(절전·최대 절전 복귀, 창 끌기 멈춤)이 생기면 그 프레임의 `unscaledDeltaTime` 누적값을 0으로 버리고 오프라인 경로만 돌린다(한도 적용, 정산 창). 같은 틈을 두 번 계산하지 않기 위해서다. 불러올 때 `lastSaveUtc`가 지금보다 미래면 지금으로 다시 맞추고, 건축·주문 타이머의 **남은 시간**은 그대로 보존한다. `DateTime.Now`는 쓰지 않고 DateTime을 직렬화하지 않는다. UTC Ticks를 `long`으로 저장한다 | 중 |
| 오프라인 정산 | 경과 = clamp(UtcNow − last, 0, 한도). 효율은 100%다. 60초 스텝으로 돌린다(24시간 = 1,440스텝). 한도는 가게 단계별 8 → 12 → 16 → 20 → 24시간. '그동안 있었던 일' 창에 재료, 제작, 판매, 쌓인 주문, 해금된 추억, 달성한 업적을 보여 준다 | 중 |
| 세이브/로드 | JSON을 `persistentDataPath`에 저장한다. `saveVersion`과 단계별 마이그레이션, Dictionary 대신 List. `.tmp`에 쓴 뒤 `File.Replace`로 본 파일과 `.bak`을 바꾼다(첫 저장은 `File.Move`). 불러올 때는 본 파일 → `.bak` → 새 게임 순서로 시도한다. 자동 저장은 30초마다, 중요한 이벤트 뒤(구매, 강화 성공, 추억 해금, 엔딩), `OnApplicationFocus(false)`, 종료 때. 에디터 Play 모드는 **별도 파일 이름**(`save_editor.json`)을 써서 테스트 빌드의 세이브(`save.json`)를 덮어쓰지 않는다. Company/Product Name은 1주 차에 확정하고 바꾸지 않는다(세이브 경로가 된다) | 중 |
| 큰 숫자 & BalanceConfig | double을 쓰고 경제 상한은 1e15 이하로 설계한다. 표기는 만·억·조로 한다(1만 미만은 쉼표, 그 이상은 '3억 2,500만'). 모든 수치는 `Balance.csv` → `BalanceConfig` 하나에 둔다 | 하 |

| 가게·추억 | 5 | 2~5단계 확장(단계형 업적 1개), 추억 10개/날짜 추억 M17을 뺀 19개 전부, 엔딩 보기, 편지 다시 읽기 |
| 방문 | 2 | 오프라인 정산 첫 수령, 서로 다른 날 7일 접속 |
| 숨김 | 7 | 조수 쓰다듬기 100회, 새벽 2~4시에 가게 열기('또 안 자지?'), 두 주인을 번갈아 50번 클릭, 가게 구석 숨은 물건 클릭, 사용자가 정하는 둘만의 비밀 행동 1개, {기념일1} 접속, {기념일2} 접속 |

- 날짜 숨은 업적 2개는 **별 0개 보너스**로 두고 100% 계산에서 뺀다. 선물을 건네는 날짜와 상관없이 완주할 수 있게 하기 위해서다.
- 숨은 업적은 잠겨 있을 때 '???'와 힌트 한 줄만 보인다. 엔딩 뒤에는 힌트가 한 단계 더 드러난다.
- 새벽·날짜 업적은 로컬 시간대로 판정한다(저장은 UTC, 판정할 때만 로컬로 바꾼다).

### 6-2. 흐름과 보상
- **엔딩 전에 자연스럽게 얻는 업적은 약 28개(별 약 40개)**가 목표다. 나머지(+10, ★5, 1억 코인, 숨김)는 엔딩 뒤 노가다 목표가 된다.
- 별 1개마다 영구 판매가 +0.5%가 붙는다(도감 테두리와 함께 쓰는 작은 성장 보상).
- **별 마일스톤**
  - 15개(2~3일째): 추억
  - 35개(5~6일째): 추억
  - 55개(엔딩 후): 추억
  - 70개(엔딩 후): **비밀 편지(P.S.)**
- 알림은 화면 오른쪽 아래 토스트다. 약 3초씩 대기열로 하나씩 보여 주고 효과음을 낸다. 업적 창에는 분류별 진행률 바를 둔다.

### 6-3. 구현
- `AchievementDef`: id, 분류, 조건 타입, 목표치, 별, 숨김, 연결 추억 id.
- 조건 타입(enum 약 10종): 누적 카운터, 최고 강화, 도감 수, ★ 수, 가게 단계, 시각대, 날짜, 특정 클릭, 연속 실패, 접속일. 강화와 ★ 승급은 연속 4회 실패 뒤 확정 성공이므로 '연속 실패'의 목표치는 4 이하만 허용한다(가져오기 때 검사).

- 업적을 더할 때는 CSV 한 줄만 추가하면 된다.

## 7) 추억 해금 설계

### 7-1. 원칙

- **도감 설명 28줄**: 상품과 소품 칸을 열 때마다 짧은 선물 문구가 나온다. 예: '{받는사람}이 좋아하던 딸기로 만든 타르트'.
- **소품 8종**: 받는 사람과 얽힌 물건(영수증, 기차표 등)이다. 한 줄 사연은 도감에 들어간다.

### 7-4. 연출
- 해금되면 조수가 '편지 왔어요!' 말풍선을 띄우고 우편함이 반짝인다. **팝업은 자동으로 뜨지 않는다.** 대기열에 쌓아 두었다가 플레이어가 원할 때 연다.
- 우편함을 클릭하면 봉투가 열리고(2프레임), 사진이 폴라로이드 프레임에 담겨 올라오고, 글이 한 글자씩 나타난다. 클릭하면 전체가 한 번에 보인다. 다 보면 앨범에 붙는다.
- 앨범은 시간 순서대로 된 페이지다. 새 추억에는 빨간 점이 붙는다. 잠긴 칸은 봉투 실루엣과 힌트('가게에 2층이 생기면…', '빵을 전부 만들어 보면…')로 보여 준다.
- 사진은 도트로 변환한 버전만 게임에 들어간다.
- (선택 아이디어) 사용자가 원본 사진도 꼭 보여 주고 싶다면, 원본은 도트 임포트 규칙(`Art/Pixel/`)에서 빠진 별도 폴더에 두고 Bilinear 필터를 쓴다. 기본 설계에는 넣지 않는다.

### 7-5. 제작 방식
- 임시 추억 카드 20장으로 게임을 먼저 끝까지 완성한다.
- **사진 도트 변환**: Claude가 쓴 C# **에디터 도구**가 사용자 PC에서 돈다. 평균값 축소(긴 변 약 128~256px), 프로젝트 팔레트로 양자화, 미리보기를 제공하고, 결과 PNG를 `Art/Pixel/Memories/`에 저장한다. 그 뒤 Pixelorama에서 손본다. AI 그림을 정리하는 도트 정리 도구와 같은 도구다. **사진은 Claude에게도, AI 그림 서비스에도 보내지 않는다.**
- **원본 사진은 저장소 루트의 `private/` 폴더**(.gitignore로 제외)에만 둔다. 커밋하는 것은 최종 도트 PNG뿐이다.
- 일정: 질문 10개 답은 **6주 차**, 스킨과 스타일 기준 시트는 **8주 차**, 그림 자리 형식은 **18주 차**에 정하고, 실제 사진·글·편지는 **20주 차(콘텐츠 마감)**까지 넣는다. **21주 차 말 기능 동결**.
- `MemoryDef`: id, 제목, 날짜 문구, 종류, 이미지, 본문 txt, 해금 조건, 잠겨 있을 때 보일 힌트.

## 8) 엔딩 설계

### 8-1. 발동
5단계 '{가게이름}' 건축을 완성하고 수령하면 주문 게시판에 **'마지막 주문'** 특별 카드가 붙는다. 손님 걷기 연출이 들어가 있으면 편지 배달부가 게시판까지 걸어와 붙이고, 없으면 카드가 반짝이며 나타난다. 다음 목표 바에 준비물이 미리 보인다.

**{최종상품} 레시피**
- 4계열 대표 상품 ★3 이상 1개씩
- 희귀 재료 4종
- 큰 반짝이 가루 1개
- 코인

지금까지 배운 시스템을 전부 한 번씩 쓰는 졸업 과제이고, 준비에는 약 1일이 걸리는 것이 목표다. 강화 수치는 엔딩 필수 조건에 없다. ★3 확률은 작업대 +0~+3에서도 마지막 주문 준비 약 1일 안에 4계열 ★3이 모이도록 맞춘다(★ 승급이 없어도 엔딩에 닿는다. 시뮬레이터로 확인).

### 8-2. 시작 방식
{최종상품}을 만들어 마지막 주문에 납품하면 카운터에 **'오늘은 가게 문 닫기'** 버튼이 생기고, '10분쯤 여유가 있을 때 눌러 주세요'라는 안내가 뜬다. 옆에 켜 둔 창에서 엔딩이 갑자기 시작되지 않는다.

### 8-3. 시퀀스 (약 4~6분, 코루틴, Timeline 불필요)
1. **해 질 녘**: 가게 위에 깐 전체 화면 **틴트 Image**의 색과 알파를 트윈해서 낮 → 노을 → 밤으로 바꾼다. BGM이 엔딩 곡으로 크로스페이드된다.
2. 손님들이 인사 말풍선을 띄우며 나가고(걷기 연출이 없으면 페이드), 조수들이 잠든다. 진열대 조명과 간판 {가게이름}이 켜진다. 조명은 **빛 스프라이트 Image의 알파 트윈**이다.
3. 두 주인이 카운터에 나란히 앉고, 테이블에 {최종상품}이 놓인다.
4. **앨범 슬라이드쇼**: 해금한 추억만 시간 순서대로 장당 3~4초 보여 준다. 날짜 문구 캡션이 붙는다.
5. **편지**: 편지지 UI에 {편지}가 한 글자씩 타이핑된다. 클릭하면 페이지가 한 번에 나오고, 여러 페이지를 넘길 수 있으며, 자동으로 넘어가지 않는다.
6. **엔딩 일러스트**: 불 켜진 간판 아래의 두 사람. 문구는 '{함께한날}일째, 그리고 앞으로도'. 날짜가 없으면 '{받는사람}에게, {나}가'.
7. **크레딧 + 여정 통계**: '우리의 가게는 N일 만에 완성됐어요', 총 클릭 수, 만든 상품 수, 강화 성공 횟수. 사용한 AI 도구, 폰트(OFL), 사운드 출처는 `docs/CREDITS.md`와 같은 내용을 보여 준다.
8. **다음 날 아침**: 가게 벽에 '편지' 액자가 걸린다(클릭하면 다시 읽기, 공개 업적 '편지 다시 읽기'). 앨범에 '엔딩 다시 보기'가 생긴다.

### 8-4. 엔딩 후
- 가게는 계속 영업한다. +8~+10 강화와 ★5 승급 목표가 강조된다.
- 숨은 업적 힌트가 한 단계 더 드러나고, 보너스 추억 M18~M20과 **P.S.(별 70개)**가 새 목표가 된다.
- 엔딩 뒤 콘텐츠는 1~3주 정도의 선택 노가다다.
- 엔딩 도달 여부와 편지 해금 상태는 세이브에 따로 한 번 더 기록한다(진행이 소실되는 사고에 대비).

## 9) 진행 페이스

> 이 절의 표는 모두 **목표값**이다. 결과가 아니다. 밸런스 시뮬레이터로 검증하고 `Balance.csv`에서 조정한다.

### 9-1. 페이스를 정하는 손잡이
| 손잡이 | 값(잠정) | 역할 |
|---|---|---|
| 건축 타이머 | 2단계 15분, 3단계 2시간, 4단계 6시간, 5단계 10시간 | 몰아서 하는 플레이의 하한. 완성 뒤 **수령해야** 다음 단계가 열린다 |
| 오프라인 한도 | 1단계 8시간 → 2단계 12시간 → 3단계 16시간 → 4단계 20시간 → 5단계 24시간 | 하루 1번 여는 사람의 엔딩이 지나치게 늦어지지 않게 한다. 리서치의 간이 모델에서 단계형 한도는 24시간 고정과 같은 결과를 냈고(보통 약 6.9일, 하루 1번 약 9.9일), 8시간 고정은 하루 1번 플레이어를 약 21일로 늘렸다. 이 모델에는 이산 게이트가 없으므로 시뮬레이터로 다시 확인한다 |
| 주문 게시판 | 2시간마다 1장, 칸 3(업그레이드로 4) | 오프라인에도 쌓이지만 칸이 차면 멈춘다. 하루 1번 여는 사람은 하루 최대 약 12장 중 3~4장만 받는다. 시뮬레이터 결과를 보고 **쌓인 시간만큼 보상 배율을 올릴지, 칸 상한을 늘릴지** 정한다 |
| 확장 비용 | 코인 + 하트 + 도감 수(3단계 5종, 4단계 10종, 5단계 16종) | 수집을 메인 진행에 묶는다 |
| 선물 속도 | ×1.0 / ×1.5 / ×2.5 | 받는 사람용 안전장치. 타이머에도 적용된다 |

- 창고 용량은 '현재 오프라인 한도만큼 생산해도 넘치지 않을 정도'로 넉넉하게 둔다. 만든 상품은 상하지 않는다.
- 반짝이 가루는 **제작만으로도 강화에 충분히** 나오게 맞춘다. 분해와 주문 보상은 보조다. 시뮬레이터가 가루 수지를 따로 출력한다.

### 9-2. 밸런스 시뮬레이터
- `Balance.csv`를 읽는 Python 스크립트(`tools/`)다. Python 쪽 도구는 이것 하나뿐이고, C# 코어는 헤드리스 테스트로 따로 확인한다.

- **출력**(플레이어 유형 4종: 하루 3~4번, 하루 2번, 하루 1번, 첫날 3시간 몰아서)

  - 의미 있는 행동 사이의 최장 대기
  - 추억별 해금일
  - 2분 넘는 대기 횟수(몰아서 하는 세션의 빈 시간)
  - 반짝이 가루 공급원별 수지
  - 마지막 주문 준비 게이트에서 작업대 +0~+3일 때 4계열 ★3이 모이는 시간

### 9-3. 1일째 (첫 접속 약 30분 + 저녁)

## 10) 화면 구성 (창 모드 PC)

### 10-1. 렌더링 구조: 전부 uGUI
- **Screen Space - Overlay 캔버스 하나**에 모든 것을 올린다. 가게 단면도 UI Image 레이어(배경, 확장 레이어 4세트, 가구, 캐릭터)로 만든다. 월드 SpriteRenderer, Physics2DRaycaster, Collider2D는 쓰지 않는다.
- Canvas Scaler는 **Constant Pixel Size**이고, Claude의 `IntegerCanvasScaler`가 `scaleFactor = max(1, floor(min(W / 기준W, H / 기준H)))`를 계산해 창 크기가 바뀔 때마다 갱신한다.
- Canvas Scaler의 **Reference Pixels Per Unit = 16**(스프라이트 PPU와 같게. 다르면 Set Native Size에서 크기가 어긋난다). Canvas의 **Pixel Perfect**를 켠다.
- 루트 레이아웃은 앵커로 늘여서, 창이 기준 비율보다 넓거나 높으면 남는 공간은 가게 배경색 여백이 된다(검은 띠 없음).
- **Pixel Perfect Camera, Light 2D, 별도의 2D Pixel Perfect 패키지는 쓰지 않는다.** Overlay 캔버스에는 Pixel Perfect Camera가 적용되지 않고, Light 2D는 UI를 비추지 않는다. 밤 조명은 틴트 Image와 빛 스프라이트 알파로 만든다(8-3).
- UI 애니메이션(조수, 손님, 우편함 반짝임)은 Claude의 `UISpriteAnimator`(스프라이트 배열 + fps, unscaled time)로 돌린다.
- 입력은 uGUI 이벤트(`Button.onClick`, `IPointerDownHandler` 등)만 쓴다. `UnityEngine.Input`은 쓰지 않는다. ESC 뒤로는 Input System(`Keyboard.current.escapeKey` 또는 UI Cancel 액션)으로 읽는다. EventSystem은 `InputSystemUIInputModule`을 쓴다.

### 10-2. 기준 해상도와 창 크기
- **기본 기준 해상도는 640x360**이다. **2주 차 목업**에서 480x270과 비교해 확정한다. 가장 긴 문장(도감 설명, 업그레이드 줄, 편지 한 페이지)을 두 해상도에 넣고 내 모니터에서 본다.
- 받는 사람이 **1366x768 노트북**을 쓰면 640x360 ×2(1280x720) 창이 제목 표시줄과 작업표시줄 때문에 들어가지 않아 ×1로 떨어진다. 이 경우 **480x270**을 고르고 본문은 **Galmuri9**, 슬라이드 패널 폭은 **240px**로 한다.
- 창 크기 옵션은 고정 배율 목록이 아니다. 코드가 **모니터 작업 영역**(작업표시줄 제외, Win32 `SystemParametersInfo(SPI_GETWORKAREA)`, 실패하면 모니터 해상도에서 여유를 뺀 값)에 제목 표시줄까지 넣어 들어가는 **가장 큰 정수 배율**을 계산해 기본값으로 쓰고, 그보다 작은 정수 배율과 **전체 화면**을 고를 수 있게 한다.
- 창 크기는 게임 안에서 `Screen.SetResolution`으로 관리하고 세이브 설정에 기억한다. Windows 레지스트리가 마지막 창 크기를 기억하므로, Player Settings의 기본 크기를 바꿔도 테스트 PC에서는 달라 보이지 않을 수 있다.

### 10-3. 글꼴
- 본문 **Galmuri11**(한글 글자 폭 12px), 제목 **Galmuri14 또는 Neo둥근모**. 480x270을 고르면 본문은 Galmuri9. 모두 **OFL 1.1**이다. 빌드 폴더에 OFL 라이선스 텍스트를 넣고 게임 크레딧에 폰트를 표기한다.
- TMP 폰트 에셋은 **정적(Static)**으로 만들고, **한글 11,172자 전체(AC00–D7A3) + ASCII + 문장 부호 + 자모**를 넣는다. Dynamic은 .asset이 계속 바뀌어 git 충돌을 만들고, 글자셋을 골라 넣으면 나중에 쓴 편지의 새 글자가 □로 나온다.
- 설정: 아틀라스 **2048x2048**, Render Mode **RASTER_HINTED**, Sampling Point Size = **폰트의 네이티브 픽셀 크기**(Galmuri11은 12), Padding 1~2, 아틀라스 텍스처 필터 **Point**, 머티리얼 셰이더 **TextMeshPro/Bitmap**. 아틀라스는 2048x2048로 고정한다. 제목 폰트처럼 글자가 커서 다 들어가지 않으면 Padding 1로 줄이고, 그래도 안 되면 제목 폰트만 UI 문구에 쓰는 글자로 줄인다(제목에는 Claude와 사용자가 정한 UI 문구만 쓴다. 1~2주 차에 확인).
- 글꼴 크기는 **네이티브 크기의 정수배**만 쓴다(Galmuri11이면 12, 24).
- TMP Settings에서 **'Use Modern Hangul Line Breaking Rules'**를 켠다(어절 단위 줄바꿈).
- 폰트 파일은 `*Bitmap*` TTF가 아니라 **외곽선 TTF**를 쓴다.
- RASTER_HINTED 아틀라스 글리프 깨짐 버그가 6000.3.18f1에서 고쳐졌으므로 그 이상 버전이 필요하다(설치된 6000.3.25f1이면 된다).

### 10-4. 런타임과 Player Settings
- 부트스트랩: `QualitySettings.vSyncCount = 0`(0이 아니면 `targetFrameRate`가 무시된다), 포커스일 때 약 60fps, 비포커스일 때 약 15~30fps(`OnApplicationFocus`에서 바꾼다).
- Player Settings: **Windowed, Resizable Window, Run In Background, Force Single Instance**(두 개를 켜서 세이브를 서로 덮어쓰는 사고 방지). Company Name과 Product Name은 1주 차에 확정하고 바꾸지 않는다.
- 비활성 음소거는 설정에서 고른다.

- **프롬프트 틀**: Claude가 `docs/ART_GUIDE.md`에 그림 종류별 프롬프트를 쓴다. 모든 프롬프트는 같은 스타일 문구로 시작하고, 그림 안에 글자를 넣지 않고, 배경은 투명 또는 단색으로 요청한다. 같은 종류는 한 번에 몰아서 뽑는다.
- **모든 AI 결과는 도트 정리 도구를 거친다**: 목표 크기 격자에 맞추기(가짜 픽셀 제거), 프로젝트 팔레트로 양자화, 배경 투명화, 미리보기. 그다음 `Art/Pixel/`에 넣는다. 몇 픽셀 어긋난 곳만 Pixelorama에서 손본다.
- **UI 틀과 이펙트는 Claude의 코드로** 만든다(UI 틀·이펙트 생성 메뉴). 팔레트 색만 쓰므로 AI 그림과 자연스럽게 어울린다.
- **받는 사람 사진은 AI 서비스에 올리지 않는다.** 두 주인은 특징(머리 모양과 색, 자주 입는 옷, 안경 같은 소품)을 글로 설명해서 만든다.
- 폰트는 `Art/Fonts/`에 라이선스 사본과 함께 둔다. 사용한 AI 도구와 약관, 폰트, 사운드를 `docs/CREDITS.md`에 기록하고 게임 안 크레딧에도 보여 준다.
- ★ 단계, 강화 외형, 잠김 실루엣, 밤 조명, 손님과 조수 색은 **코드 틴트와 오버레이 Image**로 처리한다(추가 그림 0).

## 12) 위험 요소와 대응

| 위험 | 대응 |
|---|---|
| **밸런스 붕괴**(하루 만에 끝나거나 3주가 걸림) | 모든 수치를 `Balance.csv` 하나에 둔다. 페이스 표는 목표값이고, 이산 게이트를 넣은 시뮬레이터로 v0(1~2주) → v1(3주 초, 코드보다 먼저) → v2(10~12주) → v3(14주) → v4(첫 실제 날짜 플레이 뒤) 순서로 확인한다. 16~17주에 사용자가 임시 추억 테스트 빌드로 첫 실제 날짜 완주를 시작하고, 22~24주에 두 번째 완주를 한다. 선물 속도 설정도 둔다 |
| **시뮬레이터와 게임 코드가 어긋남** | 코어를 UnityEngine 없는 순수 C#으로 쓰고 Claude가 dotnet으로 헤드리스 테스트한다. 같은 `Balance.csv`를 읽는다. 저장 가능한 PRNG와 고정 처리 순서로 결정성을 지키고, '1초 × 3600 ≈ 60초 × 60'을 테스트한다 |
| **세이브·오프라인 버그로 진행 소실** | `Simulate(dt)` 하나로 온라인과 오프라인을 통일한다. UTC Ticks는 `long`으로 저장하고 `DateTime.Now`와 DateTime 직렬화는 쓰지 않는다. `.tmp` → `File.Replace` + `.bak`(첫 저장은 `File.Move`), 본 파일 → `.bak` → 새 게임, `saveVersion` 마이그레이션, List 사용. 30초마다, 중요 이벤트 뒤, 포커스를 잃을 때, 종료 때 저장한다. 설정에 '백업에서 복원'을 둔다 |
| **절전 복귀·시계 오류** | 매 프레임 UTC 경과가 5초를 넘으면 오프라인 경로(한도, 정산 창)로 보낸다. 불러올 때 `lastSaveUtc`가 미래면 지금으로 맞추고 타이머의 남은 시간을 보존한다. 시계를 되돌려도 벌칙은 없다(음수 경과는 0). 디버그 '시계 ±N시간'으로 테스트한다 |
| **Time.deltaTime 상한으로 생산 손실** | `unscaledDeltaTime`을 누적해 1초 고정 스텝으로 돌린다 |
| **에디터와 테스트 빌드의 세이브 충돌** | 에디터는 `save_editor.json`을 쓴다. '세이브 초기화'는 `#if UNITY_EDITOR \|\| DEVELOPMENT_BUILD` 안에만 둔다. Company/Product Name은 1주 차에 고정한다. Force Single Instance를 켠다 |
| **범위 팽창**(필수 시스템 약 25개) | 우선순위를 ① 코어(채집, 조수, 제작, 판매, 업그레이드, 세이브, 오프라인) ② 확장, 주문 게시판, 추억, 엔딩(임시 추억으로 끝까지 연결) ③ 강화, ★, 도감, 업적, 안내 카드 ④ 연출과 선택 기능 순으로 잡는다. 주문 게시판은 엔딩에 필요하므로 필수다. 21주 차 말에 기능을 동결하고, 새 아이디어는 `IDEAS.md`에 적어만 둔다 |
| **사용자 작업 시간 초과** | 일러스트는 엔딩 1장만 필수로 한다. 그림은 AI로 뽑고 정리 도구로 통일하며, Claude가 프롬프트를 미리 써 둔다. UI 틀, 이펙트 조각, UI 뼈대, 플레이스홀더 아이콘은 에디터 메뉴가 만든다. 일반 텍스트는 Claude가 초안을 쓰고 사용자는 개인 텍스트 약 120줄과 편지만 쓴다. 아트 교체는 13주부터 나눠서 한다 |
| **받는 사람 정보가 늦게 정해짐** | 테마와 추억을 데이터로 분리하고, 색 블록 아이콘과 임시 카드로 먼저 끝까지 완성한다. 질문 10개는 6주, 스킨과 스타일 기준 시트는 8주, 콘텐츠 마감은 20주, 기능 동결은 21주 말이다. 테마 검사 창으로 빈칸을 추적한다 |
| **강화·노가다 스트레스** | 강화와 ★ 승급 모두 파괴·하락·소멸이 없다. 확률과 천장 카운터를 공개한다. 실패하면 다음 확률 +10%p, 연속 4회 실패 뒤 5번째는 확정이다. 엔딩 조건에는 강화 수치도 ★ 승급도 없다. 누르고 있기 채집, 첫 추억은 5분 안에, 누적 접속 보상, 선물 속도 |
| **반짝이 가루 부족** | 가루는 제작 레시피가 주 공급원이다. 분해(권장 시스템)나 주문 보상이 빠져도 강화가 막히지 않는지 시뮬레이터로 확인한다 |
| **하루 1번만 여는 받는 사람** | 오프라인 한도를 단계별로 24시간까지 늘리고, 창고를 넉넉하게 두고, 상품이 상하지 않게 한다. 주문은 오프라인에도 쌓이지만 칸 상한이 있으므로, 시뮬레이터 결과로 보상 배율이나 칸 상한을 조정한다 |
| **몰아서 하는 첫 세션의 빈 시간** | 강화, ★ 승급, 도감, 주문, 분해가 대기 시간을 채운다. 시뮬레이터로 '2분 넘는 대기 횟수'를 추적한다 |
| **혼자 플레이할 때 시스템을 모르고 지나침** | 첫 3분 튜토리얼 뒤에도 시스템이 처음 열릴 때 안내 카드(약 10종)를 한 번씩 띄운다. 다음 목표 바가 새 시스템을 먼저 가리킨다. 설정에 '도움말 다시 보기', 이틀 정체 시 선물 속도 힌트 |
| **실수로 진행을 날림** | 새로 시작은 두 단계 확인. 설정의 '백업에서 복원'. 엔딩·편지 해금 상태는 세이브에 따로 한 번 더 기록한다 |
| **옆에 켜 둘 때의 방해와 CPU** | vSync 0 + 비포커스 15~30fps, 음소거 옵션, 팝업 대신 토스트와 우편함 대기열, 엔딩은 버튼을 눌러야 시작 |
| **도트가 흐리거나 고르지 않음** | 전부 uGUI + `IntegerCanvasScaler`(Constant Pixel Size, 정수 배율만), Reference PPU 16, Canvas Pixel Perfect. 스프라이트는 Point, 압축 없음. 움직이는 요소는 정수 픽셀로 반올림한다. Pixel Perfect Camera와 Light 2D에 기대지 않는다 |
| **해상도와 한글 가독성** | 기본 640x360. 2주 차 목업에서 480x270과 비교해 확정한다(1366x768 노트북이면 480x270 + Galmuri9 + 240px 패널). 창 크기는 작업 영역에 맞춘 최대 정수 배율을 코드가 계산한다 |
| **한글 폰트가 깨지거나 □가 나옴** | 11,172자 전체를 담은 정적 TMP 폰트 에셋(RASTER_HINTED, Bitmap 셰이더, Point, 네이티브 크기 정수배), 외곽선 TTF, 한글 줄바꿈 옵션, Unity 6000.3.18f1 이상. 1~2주 차에 긴 글 가독성까지 확인한다 |
| **CSV 한글 깨짐과 데이터 오류** | UTF-8만 쓴다('CSV UTF-8' 또는 Google 스프레드시트). RFC 4180 파서, 날짜형 칸은 문자열로 읽기, 자동 재가져오기, 오류는 테마 검사 창에 표시 |

| **초보자 UI 배치 노동** | UI 뼈대는 Claude의 에디터 메뉴가 만든다. 목록형 UI는 템플릿 프리팹 1개를 코드로 복제한다. 참조는 이름으로 자동 연결한다. 기준 해상도가 하나라 레이아웃 경우의 수도 적다 |
| **Claude↔사용자 Git 충돌** | Claude는 `.unity`, `.prefab`, `.asset` YAML을 편집하지 않는다. 사용자는 새 스크립트를 Pull한 직후 Unity가 만든 `.meta`를 바로 커밋한다. Claude는 바이너리를 커밋하지 않는다(플레이스홀더 아이콘은 사용자 PC의 에디터 메뉴가 만든다). `.gitattributes`의 LFS 목록에 `*.aseprite`, `*.ase`, `*.pxo`를 넣는다. 작업 전 Pull, 작업 후 Push |
| **AI 그림의 품질과 일관성** | 2주 차에 무료 체험으로 시험 생성해 도구를 정한다. 메인 도구는 하나만 쓴다. 8주 차 스타일 기준 시트(팔레트, 크기, 기준 그림)를 모든 생성에 참고 그림으로 넣고, Claude의 프롬프트 틀로 문구를 통일한다. 모든 결과는 도트 정리 도구로 격자와 팔레트를 맞춘다. 같은 캐릭터의 동작 프레임이 흔들리면 AI 동작 생성 결과를 기준 프레임에 맞춰 손질한다. 그래도 특정 종류가 끝내 만족스럽지 않으면 그 종류만 대안을 다시 논의한다 |
| **AI 도구 약관과 개인정보** | 사용한 도구의 약관(개인·비상업 사용 허용 여부)을 `docs/CREDITS.md`에 기록하고 게임 크레딧에 표기한다. 받는 사람 사진은 AI 서비스에 올리지 않는다. 폰트는 `Art/Fonts/`에 OFL 사본과 함께 둔다 |
| **개인정보와 선물 비공개** | 저장소는 끝까지 비공개. 원본 사진은 `.gitignore`로 제외한 `private/`에만 두고, 사진 변환은 사용자 PC의 에디터 도구로 한다(사진이 PC 밖으로 나가지 않는다). 커밋은 최종 도트 PNG만 한다. 지인 테스트는 개인 콘텐츠가 없는 예시 스킨 빌드로 하고, 실제 콘텐츠 빌드는 사용자만 플레이한다 |
| **Windows 실행 차단** | 서명 없는 exe는 SmartScreen과 Windows 11 **스마트 앱 컨트롤(SAC)**에 막힐 수 있다. 25주 차에 SAC가 켜진 PC에서 실행해 본다. 받는 사람에게 SAC를 끄라고 하지 않는다. 인터넷 다운로드의 Mark-of-the-Web을 피하려고 **USB로 전달**하고, 실행 방법 안내 카드를 함께 준다. 1366x768 노트북과 화면 배율 125~150% PC에서도 테스트한다. 새벽·날짜 업적은 로컬 시간대로 테스트한다 |
