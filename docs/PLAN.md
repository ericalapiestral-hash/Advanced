> 플랫폼: Windows PC · 싱글플레이 · 오프라인 · 기간: 최소 6개월 (26주)

## 1. 목표

1. 받는 사람이 설명 없이 혼자 플레이하고, **며칠~2주 안에 엔딩(편지)**에 닿는다.
2. 가게가 자라고 업적을 모을 때마다 **두 사람의 추억**(사진, 짧은 글, 도트 그림)이 열린다.
3. 화면은 **도트 에셋 한 가지 계열**로 통일해서 아기자기하고 일관되게 보인다.
4. Unity 에디터로 게임을 조립하는 흐름(배치, 연결, 테스트, 빌드)을 처음부터 끝까지 경험한다.
   코드는 Claude가 쓰고, 한국어 주석을 읽으며 어떻게 돌아가는지 이해한다.

## 2. 게임 한눈에 보기

창 옆에 켜 두는 한 화면짜리 도트 가게다. 두 주인(받는 사람과 나)이 재료를 모으고, 상품을 만들어 팔고,
강화하고, 도감을 채우며 손수레 노점을 '{가게이름}'으로 키운다. 가게가 자랄 때마다 우편함에 추억이 도착하고,
마지막 주문을 완성한 밤에 편지가 열린다. **캐릭터를 걷게 하는 조작은 없다.** 모든 조작은 클릭과 메뉴로 한다.

### 핵심 루프
1. **채집**: 채집터를 클릭하거나 누르고 있으면 재료가 나온다.
2. **자동화**: 코인으로 조수를 고용하면 알아서 채집, 제작, 판매한다. 게임을 꺼도 쌓인다 (가게 단계에 따라 최대 8~24시간).
3. **제작, 판매**: 재료로 상품을 만들어 진열대에서 팔고, 주문 게시판의 주문을 납품한다.
4. **강화, 수집**: 도구와 작업대를 강화하고, 상품의 ★을 올리고, 도감을 채운다.
5. **가게 확장**: 코인, 하트, 도감 수를 채우면 가게가 한 단계 커지고 추억이 온다.
6. **업적**: 업적마다 별을 받는다. 별이 모이면 추억과 비밀 편지(P.S.)가 열린다.

### 고른 세 가지 노가다가 들어가는 자리
| 고른 방식 | 게임 안에서 |
|---|---|
| 클릭 + 방치 | 채집 클릭, 조수 자동 생산, 오프라인 정산 ('그동안 가게에서 있었던 일') |
| 강화, 수집 | 장비 강화 +0~+10 (파괴·하락 없음), 상품 ★1~★5 승급, 도감 32칸 |
| 채집, 제작, 가게 운영 | 채집터 4곳, 상품 20종, 진열·판매, 주문 게시판, 가게 5단계 확장 |

### 분량
| 항목 | 개수 | 항목 | 개수 |
|---|---|---|---|
| 가게 단계 | 5 | 업그레이드 | 12종 |
| 채집터 / 재료 | 4 / 8 | 강화 장비 | 6종 |
| 상품 | 20 + 최종 상품 1 | 도감 칸 | 32 |
| 조수 | 6종 (그림 3종 + 색 바꾸기) | 업적 | 45 (숨김 7) |
| 추억 | 20 + 편지 + P.S. | 화면 | 10 + 오버레이 5 |

### 플레이 시간 목표 (밸런스 시뮬레이터로 확인)
| 플레이 습관 | 엔딩 |
|---|---|
| 하루 3~4번 | 6~8일째 |
| 하루 1번 | 10~12일째 |
| 어떤 경우든 | 14일을 넘지 않게 |

엔딩 뒤에도 가게는 계속 열린다. ★5, +10 강화, 숨은 업적, 비밀 편지가 1~3주짜리 선택 목표로 남는다.

## 3. 역할 분담

| 나 | Claude |
|---|---|
| Unity 에디터 작업: 에셋 가져오기, UI 확인·조정, 스크립트 연결, 값 조정 | C# 코드 전부 + 에디터 자동화 도구 (UI 뼈대 생성, 임포트 자동 설정, 플레이스홀더 아이콘 생성, 사진 도트 변환기) |
| 에셋 고르기, 재채색, 꼭 필요한 그림 몇 장 | 기능마다 에디터 설정 방법 단계별 안내 |
| **개인적인 글**: 추억 글, 사진 캡션, 두 주인 대사, 도감 설명, 편지, P.S. | **일반 텍스트 초안**: UI 문구, 업적 이름·설명, 튜토리얼, 힌트 (말투는 내가 다듬는다) |
| 플레이 테스트, 버그 보고 | 밸런스 시뮬레이터, 헤드리스 테스트, 에러 원인 찾기와 수정 |

> Claude는 Unity를 직접 실행할 수 없다. 그래서 모든 기능은 **내가 에디터에서 실행해 봐야 완성**이다.
> 다만 게임의 핵심 계산(생산, 판매, 오프라인 정산)은 Unity 없이도 돌아가는 순수 C#으로 짜서, Claude가 자기 환경에서 테스트한다.

### 기능 하나를 만드는 순서
1. **나**: 만들 기능을 말한다 (보통은 아래 일정의 다음 항목). 에디터에서 작업하던 게 있으면 먼저 커밋하고 푸시한다.
2. **Claude**: 코드를 작성해 GitHub에 푸시하고, 에디터 설정 방법을 알려준다.
3. **나**: GitHub Desktop에서 **Pull** → Unity로 돌아가면 자동으로 컴파일된다 → **새로 생긴 `.meta` 파일을 바로 커밋**한다 → 안내대로 설정 → **Play**로 테스트.
4. **에러가 나면**: Console 창의 빨간 에러를 클릭하고, 아래에 나오는 전체 내용을 복사하거나 스크린샷으로 보낸다.
5. **잘 되면**: 에디터에서 작업한 내용(씬, 프리팹)을 커밋하고 푸시한다.

- 코드에는 **한국어 주석**으로 무엇을 하는지 적는다.
- 조절할 만한 수치는 전부 `Balance.csv` 한 파일에 모은다. 코드를 몰라도 직접 튜닝할 수 있다.
- **Claude는 씬(.unity), 프리팹(.prefab), 에셋(.asset) 파일을 직접 고치지 않는다.** 이 파일들은 에디터에서만 바꾼다. 서로 덮어쓰는 사고를 막기 위해서다.

## 4. 기술 스택

| 분야 | 사용할 것 | 비고 |
|---|---|---|
| 엔진 | **Unity 6.3 LTS**, 6000.3.18f1 이상 | 설치된 6000.3.25f1이면 된다. 6.4 이상으로 올리지 않는다 |
| 프로젝트 템플릿 | **Universal 2D** | Unity Hub의 Core 분류. `2D (Built-In Render Pipeline)`은 고르지 않는다 |
| UI | **uGUI + TextMeshPro** | 게임 거의 전부가 UI다. TextMeshPro는 Unity 6에서 uGUI에 들어 있으니 따로 설치하지 않는다 |
| 도트 선명하게 | Canvas Scaler **Constant Pixel Size** + Claude의 정수 배율 스크립트 | Reference Pixels Per Unit = 16, Canvas의 Pixel Perfect 켜기. Pixel Perfect Camera, Light 2D는 쓰지 않는다 |
| 기준 해상도 | **640x360** (기본) | 2주 차에 480x270과 비교해서 확정. 받는 사람의 모니터가 1366x768 노트북이면 480x270이 나을 수 있다 |
| 스프라이트 설정 | Point 필터, 압축 없음, 밉맵 끔, PPU 16 | Claude가 만든 자동 설정 스크립트가 `Art/Pixel/` 폴더에 넣는 순간 적용한다 |
| 한글 폰트 | **갈무리11** (본문), 갈무리14 또는 Neo둥근모 (제목) | 모두 OFL 라이선스. TMP 정적 폰트 에셋에 한글 11,172자 전체를 넣는다 (RASTER_HINTED, Bitmap 셰이더) |
| 데이터 | CSV (UTF-8) → 자동 가져오기 | 아이템, 레시피, 업적, 추억 등을 스프레드시트로 편집한다. 엑셀은 반드시 'CSV UTF-8'로 저장 |
| 수치 | `Balance.csv` | 게임과 밸런스 시뮬레이터가 같은 파일을 읽는다 |
| 저장 | JSON + 백업 파일 | 30초마다, 창을 벗어날 때, 중요한 일이 생길 때 자동 저장. 시간은 UTC로 기록 |
| 도트 편집 | **Pixelorama** (무료, 한국어) | 도트 작업이 재미있으면 Aseprite(유료)로 바꿔도 된다 |
| 에셋 | 한 가지 계열만 | 후보: Sprout Lands + UI Pack (유료 소액), Ninja Adventure (CC0). 개발 초반의 임시 아이콘은 Claude의 도구가 만든다 |
| 사운드 | Kenney UI 효과음 (CC0), ChipTone/jsfxr, CC0 BGM | OGG로 넣는다 |
| 버전 관리 | Git + GitHub Desktop + Git LFS | Claude가 짠 코드도 GitHub로 주고받는다 |

> 에셋 후보의 가격과 라이선스는 조사 시점 기준이다. 구입하거나 받기 전에 판매 페이지에서 다시 확인한다.

## 6. 작업 원칙

1. **작업 전에 Pull, 작업 후에 Push.** Claude와 같은 저장소를 쓰기 때문에 이 순서를 지켜야 서로 덮어쓰지 않는다.
2. **Claude의 새 스크립트를 받으면 `.meta` 파일을 바로 커밋한다.** 늦으면 씬에서 스크립트 연결이 끊긴다.
3. **색 블록으로 먼저 끝까지.** 진짜 그림과 추억은 게임이 처음부터 엔딩까지 돌아간 다음에 바꿔 끼운다.
4. **새 아이디어는 `docs/IDEAS.md`에 적어만 둔다.** 지금 단계의 일이 아니면 넣지 않는다.
5. **21주 차 끝에 기능을 동결한다.** 게임을 망치는 가장 흔한 원인은 끝나지 않는 기능 추가다.
6. **30분 넘게 막히면 질문한다.** 스크린샷이나 에러 전문을 함께 보낸다.
7. **개인 사진과 글은 조심해서 다룬다.** 원본 사진은 `private/` 폴더에만 두고 커밋하지 않는다. 사진은 Claude에게 보내지 않고 내 PC의 변환 도구로 처리한다. 저장소는 끝까지 비공개로 둔다.

## 7. 저장소 구조

```
Advanced/
├─ README.md
├─ docs/
│  ├─ PLAN.md      ← 이 문서 (일정과 규칙)
│  ├─ DESIGN.md    ← 게임 설계 상세
│  ├─ IDEAS.md     ← 나중에 할 아이디어 보관함
│  └─ CREDITS.md   ← 에셋·폰트·사운드 출처와 라이선스 (3단계에 작성)
├─ tools/          ← Claude의 밸런스 시뮬레이터, 헤드리스 테스트
├─ private/        ← 원본 사진 (커밋되지 않음)
├─ Game/           ← Unity 프로젝트 (1단계에 생성)
│  └─ Assets/
│     └─ _Project/        ← 우리가 만든 것
│        ├─ Scripts/      ← Claude가 작성하는 코드
│        ├─ Data/         ← CSV (아이템, 레시피, 업적, 추억, Balance.csv)
│        ├─ Content/      ← 추억 글, 편지
│        └─ Art/
│           ├─ Pixel/       ← 도트 그림 (자동 설정이 적용되는 폴더)
│           └─ ThirdParty/  ← 받은 에셋 팩 + 각 팩의 라이선스 사본
├─ .gitignore      ← Library 같은 자동 생성 폴더, private/ 제외
└─ .gitattributes  ← 이미지, 사운드, 도트 원본 파일은 Git LFS로 관리
```

- **저장소는 비공개(Private)로 유지한다.** 받은 에셋을 공개 저장소에 올리면 라이선스 위반이고, 선물이 미리 들통날 수도 있다.
- Git LFS에는 무료 용량 한도가 있다. 1단계에서 GitHub 설정의 사용량을 한 번 확인한다.
