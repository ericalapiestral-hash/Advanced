# 개발 계획서

> 원신 스타일의 3D 스토리 액션 게임을 만든다.
> 목적: **한 사람에게 선물하기** + **Unity 연습**
> 플랫폼: Windows PC · 싱글플레이 · 기간: 최소 6개월

---

## 1. 목표

1. 받는 사람이 **처음부터 엔딩까지 막힘 없이** 플레이할 수 있다.
2. 스토리 속에 받는 사람을 위한 이야기와 메시지가 담겨 있다.
3. 화면은 "원신 느낌"이 난다. 애니메풍 캐릭터, 카툰 렌더링, 밝고 선명한 색감.
4. Unity 에디터로 게임을 조립하는 흐름(배치, 연결, 연출, 빌드)을 처음부터 끝까지 경험한다.
   코드는 Claude가 쓰고, 한국어 주석을 읽으며 어떻게 돌아가는지 이해한다.

## 2. 범위: "원신처럼"을 어디까지 할까

원신은 수백 명이 몇 년 동안 만든 게임이에요. 그래서 원신을 통째로 만들지 않고,
**원신다운 느낌을 주는 핵심만 작게** 가져와요. 완성해서 선물하는 것이 가장 중요해요.

| 원신 요소 | 이 게임 |
|---|---|
| 거대한 오픈월드 | **작은 지역 1곳**: 마을 + 필드 + 보스 구역 |
| 4인 파티 교체 | 플레이어 캐릭터 **1명** (여유가 있으면 2명) |
| 원소 7종과 원소 반응 | 원소 **1~2종**, 반응은 0~1개 |
| 등반, 수영, 활공 | 없음. 활공은 여유가 있으면 추가 |
| 가챠, 레벨, 장비, 성유물 | 없음. 스토리 진행이 곧 성장 |
| 풀보이스 | 텍스트 대사 + 효과음 |
| 수백 시간 플레이 | **30분~1시간**짜리 완결 스토리 |

### 퀄리티 전략: 에셋은 조합하고, 코드는 Claude에게 맡긴다

- **캐릭터**: VRoid Studio로 애니메풍 캐릭터를 직접 만든다 (무료, 모델링 지식 불필요)
- **애니메이션**: Mixamo 무료 모션 (달리기, 공격, 회피, 피격 등)
- **배경과 이펙트**: 에셋 스토어의 스타일라이즈드(카툰풍) 팩
- **원신풍 화면**: 툰 셰이더 + 포스트 프로세싱(Bloom, 색보정)
- **코드**: Claude가 작성하고, 나는 에디터에서 연결하고 테스트한다

> ⚠️ 원신의 모델, 음악, 이미지를 추출해서 쓰지 않는다 (저작권 문제).

## 3. 역할 분담

| 나 | Claude |
|---|---|
| Unity 에디터 작업: 에셋 가져오기, 오브젝트 배치, 스크립트 붙이기, 값 조정 | C# 코드 전부: 조작, 전투, 대화, 퀘스트, 저장, UI 동작, 적 AI |
| 캐릭터(VRoid), 맵 꾸미기, 컷신 연출, 조명 | 기능마다 에디터에서 무엇을 어떻게 설정할지 단계별 안내 |
| **스토리와 대사 쓰기.** 선물의 핵심이라 직접 쓴다 | 에러 원인 찾기와 수정 |
| 플레이 테스트, 버그 보고 | 에디터 반복 작업을 줄여주는 자동 설정 도구 |

> Claude는 Unity를 직접 실행할 수 없다. 그래서 모든 코드는 **내가 에디터에서 실행해 봐야 완성**이다.

### 기능 하나를 만드는 순서

1. **나**: 만들 기능을 말한다 (보통은 아래 일정의 다음 항목). 에디터에서 작업하던 게 있으면 먼저 커밋하고 푸시한다.
2. **Claude**: 코드를 작성해 GitHub에 푸시하고, 에디터 설정 방법을 알려준다.
3. **나**: GitHub Desktop에서 **Pull** → Unity로 돌아가면 자동으로 컴파일된다 → 안내대로 설정 → **Play**로 테스트.
4. **에러가 나면**: Console 창의 빨간 에러를 클릭하고, 아래에 나오는 전체 내용을 복사하거나 스크린샷으로 보낸다.
5. **잘 되면**: 에디터에서 작업한 내용(씬, 프리팹)을 커밋하고 푸시한다.

- 코드에는 **한국어 주석**으로 무엇을 하는지 적는다.
- 속도, 데미지, 쿨타임처럼 조절할 만한 값은 전부 **Inspector에 노출**한다. 코드를 몰라도 직접 튜닝할 수 있게.

## 4. 기능 목록 (우선순위)

**필수: 이게 없으면 게임이 아니다**
- [ ] 3인칭 이동, 달리기, 점프, 자유 회전 카메라
- [ ] NPC 대화 시스템 (이름, 대사, 선택지)
- [ ] 퀘스트 시스템 (대화 → 이동 → 수집 → 전투 순서의 단계형)
- [ ] 전투: 일반 공격 콤보, 원소 스킬(쿨타임), 회피
- [ ] 적 2종 + 보스 1
- [ ] 컷신: 오프닝, 보스 등장, 엔딩
- [ ] 세이브/로드
- [ ] 타이틀 화면, 일시정지 메뉴, 설정(음량, 마우스 감도)
- [ ] 엔딩: 받는 사람에게 보내는 메시지

**권장: 있으면 확실히 좋아진다**
- [ ] 타격감 (히트스톱, 화면 흔들림, 이펙트, 데미지 숫자)
- [ ] 수집 요소 ("추억 조각" 같은 것. 모으면 사진이나 짧은 글이 열림)
- [ ] BGM과 효과음, 발소리
- [ ] 미니맵 또는 목표 지점 표시

**선택: 기능 동결 전까지 시간이 남을 때만**
- [ ] 원소 반응 1개 (예: 불 + 물 = 증발 → 추가 데미지)
- [ ] 활공
- [ ] 두 번째 플레이어 캐릭터와 교체
- [ ] 요리나 낚시 같은 미니게임

## 6. 일정 (26주)

주 10~15시간 작업을 기준으로 잡았어요. 단계마다 **완료 기준**이 있고,
이 기준을 통과해야 다음 단계로 넘어가요. 일정이 밀리면 기능 목록의 "선택" → "권장" 순서로 빼요.
코드를 Claude가 맡으면서 아낀 시간은 **콘텐츠와 다듬기**에 더 썼어요.

### 1단계 (1~2주): 준비
- [x] Unity Hub, Unity 6.3 LTS, Visual Studio 설치
- [ ] Unity Learn: *Unity Essentials* (Hub의 `Essentials Pathway` 템플릿). Editor → 3D → Programming(가볍게) 미션까지. 2D와 Publishing은 건너뛴다
- [ ] GitHub Desktop과 Git LFS 설치, 이 저장소를 PC에 클론 (경로는 `D:\Dev\Advanced`처럼 **영어로만**. 한글이나 공백이 들어간 경로는 일부 도구에서 문제를 일으킨다)
- [ ] 이 저장소 안에 Unity 프로젝트 생성 (위치: 저장소 폴더, 이름: `Game`, 템플릿: Universal 3D) → 커밋, 푸시
- **완료 기준**: 에디터에서 오브젝트를 배치하고, 스크립트를 붙이고, Inspector에서 값을 바꾸고, Play로 테스트할 수 있다. `Game` 프로젝트가 GitHub에 올라가 있다

### 2단계 (3~6주): 기획 + 캐릭터 조작 프로토타입
- [ ] 스토리 뼈대(시작, 중간, 끝)와 받는 사람을 위한 요소 정리 → `docs/STORY.md`
- [ ] 지역 1곳 구상 스케치 (마을, 필드, 보스 구역 배치)
- [ ] 패키지 설치: Input System, Cinemachine, Starter Assets, ProBuilder
- [ ] VRoid로 주인공 제작 → VRM 가져오기 → 툰 셰이더 적용 → Starter Assets 캐릭터를 교체
- [ ] Mixamo 모션 적용 (공격, 회피)
- [ ] ProBuilder로 회색 박스 맵 만들기
- **완료 기준**: 직접 만든 캐릭터가 회색 맵을 뛰어다니고, 점프와 카메라 회전이 되며, 클릭하면 공격 모션이 나온다

### 3단계 (7~10주): 핵심 시스템 ① 상호작용, 대화, 퀘스트
- [ ] 상호작용: 가까이 가면 `[F] 대화하기` 표시
- [ ] 대화 시스템 (ScriptableObject로 대사 데이터 관리, 선택지 지원)
- [ ] 퀘스트 시스템 (단계형, 퀘스트 트래커 UI)
- [ ] 기본 UI: 체력바, 일시정지 메뉴
- [ ] TextMeshPro 한글 폰트 에셋 만들기
- **완료 기준**: NPC와 대화 → 퀘스트 수락 → 아이템 3개 수집 → 돌아가서 보고 → 퀘스트 완료까지 이어진다

### 4단계 (11~15주): 핵심 시스템 ② 전투, 저장
- [ ] 체력과 데미지 구조, 공격 판정(히트박스)
- [ ] 3타 콤보, 원소 스킬(쿨타임), 회피(무적 시간)
- [ ] 적 AI (NavMesh: 순찰 → 추적 → 공격 → 사망)
- [ ] 적 2종 + 보스 1 (패턴 2~3개)
- [ ] 타격감: 히트스톱, Cinemachine Impulse(화면 흔들림), 이펙트
- [ ] 세이브/로드 (JSON)
- **완료 기준**: 원소 스킬로 적 무리를 쓰러뜨리고 보스를 잡을 수 있다. 저장하고 껐다 켜도 진행 상황이 남아 있다

### 5단계 (16~21주): 콘텐츠 제작 → 기능 동결
- [ ] 회색 박스 맵을 실제 맵으로 교체 (Terrain, 에셋 배치, 하늘, 조명)
- [ ] 메인 스토리 퀘스트와 대사 전부 넣기
- [ ] 컷신: 오프닝, 보스 등장, 엔딩 (Timeline)
- [ ] 수집 요소
- [ ] BGM과 효과음
- **완료 기준**: 투박해도 좋으니 **처음부터 엔딩까지** 끊기지 않고 플레이된다
- 🔒 **여기서 기능 동결.** 이후에는 새 기능을 넣지 않고 다듬기만 한다

### 6단계 (22~26주): 다듬기 + 선물 준비
- [ ] 포스트 프로세싱, 조명, 이펙트 다듬기 (원신풍 룩 완성)
- [ ] 타이틀 화면, 설정 메뉴, 엔딩 메시지, 크레딧
- [ ] 지인 1~2명에게 플레이테스트 → 버그 수정
- [ ] Windows 빌드 → **다른 PC에서** 실행 테스트 (Windows 11의 "스마트 앱 컨트롤"이 켜진 PC에서도 실행이 막히지 않는지 확인)
- [ ] 전달 방법 결정 (USB, 다운로드 링크 등)
- **완료 기준**: 처음 보는 PC에서 실행부터 엔딩까지 문제없이 돌아간다

## 7. 작업 원칙

1. **항상 플레이 가능한 상태를 유지한다.** 작업 단위가 끝날 때마다 커밋한다.
2. **작업 전에 Pull, 작업 후에 Push.** Claude와 같은 저장소를 쓰기 때문에 이 순서를 지켜야 서로 덮어쓰지 않는다.
3. **새 아이디어는 `docs/IDEAS.md`에 적어만 둔다.** 지금 단계의 일이 아니면 넣지 않는다.
4. **21주 차 끝에 기능을 동결한다.** 게임을 망치는 가장 흔한 원인은 끝나지 않는 기능 추가다.
5. **30분 넘게 막히면 질문한다.** 스크린샷이나 에러 전문을 함께 보낸다.
6. **예쁘게 만드는 일은 마지막에 한다.** 회색 박스로 재미와 흐름부터 확인한다.

## 8. 저장소 구조

```
Advanced/
├─ README.md
├─ docs/
│  ├─ PLAN.md      ← 이 문서
│  ├─ STORY.md     ← 2단계에 작성
│  └─ IDEAS.md     ← 나중에 할 아이디어 보관함
├─ Game/           ← Unity 프로젝트 (1단계에 생성)
│  └─ Assets/
│     └─ _Project/ ← 우리가 만든 것 (코드, 씬, 프리팹, 대사 데이터)
│        └─ Scripts/  ← Claude가 작성하는 코드
├─ .gitignore      ← Game/Library 같은 자동 생성 폴더 제외
└─ .gitattributes  ← 이미지, 모델, 사운드는 Git LFS로 관리
```

- 에셋 스토어에서 받은 것은 `Assets/` 바로 아래 각자의 폴더에 두고, 우리가 만든 것은 전부 `Assets/_Project/` 안에 둔다. 섞이지 않아야 나중에 찾기 쉽다.
- **저장소는 비공개(Private)로 유지한다.** 에셋 스토어 에셋을 공개 저장소에 올리면 라이선스 위반이고, 선물이 미리 들통날 수도 있다.
- Git LFS에는 무료 용량 한도가 있다. 큰 에셋 팩을 넣기 전에 GitHub 설정에서 사용량을 확인한다.
